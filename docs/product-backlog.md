## Product Backlog

| Priority | User Story (Feature) | Acceptance Criteria / Technical DoD |
| :--- | :--- | :--- |
| 🔴 **Critical** | **As:** Administrator<br>**I want:** to retain exclusivity in new user registration<br>**So that:** the corporate ecosystem is shielded against unauthorized public self-registrations. | • Complete deactivation of the public `/register` route.<br>• Creation endpoint necessarily mapped under the Backoffice middleware (`/admin/users/register`).<br>• Explicit and secure role assignment (*Roles*) at creation time. |
| 🔴 **Critical** | **As:** Authenticated Collaborator<br>**I want:** to report a fault in a factory equipment<br>**So that:** the maintenance department can initiate the repair workflow. | • **Global In-House Workflow:** Any logged-in user (Worker, Technician, or Admin) can create fault orders (`POST /tickets`).<br>• Form with required field validation: Equipment, Room, and Description.<br>• Automatic association of `Auth::id()` and immutable initial state as 'Open'. |
| 🔴 **Critical** | **As:** Maintenance Technician<br>**I want:** to change a ticket state ("In Progress" / "Closed")<br>**So that:** I can control the operational timer and document work progress. | • State transitions via Eloquent Model (`Open ➔ In Progress ➔ Closed`).<br>• The 'In Progress' state injects `in_progress_at` via server timestamp (`NOW()`) and locks the route.<br>• The 'Closed' state necessarily requires a technical report, minutes spent, and a record of **parts consumed from internal stock**. |
| 🔴 **Critical** | **As:** Administrator<br>**I want:** to manage the equipment, categories, and rooms inventory (CRUD)<br>**So that:** the company's physical mapping and infrastructure remain up to date. | • Complete structural CRUD integrated with Eloquent ORM native *Soft Deletes*.<br>• Strict validations in *Form Requests* preventing duplicate serial numbers in MySQL. |
| 🟡 **High** | **As:** Administrator<br>**I want:** to be supported by Artificial Intelligence in triage and allocation<br>**So that:** tickets are dispatched with greater accuracy and shorter wait time (SLA). | • `AIService` invocation when opening the ticket detail in Backoffice.<br>• NLP processing that cross-references the fault description with the competencies and workload volume of active technicians.<br>• 1-click dispatch saving the assisted decision via route `PATCH /admin/tickets/{id}/atribuir`. |
| 🟡 **High** | **As:** Administrator<br>**I want:** to view reactive dashboards with performance metrics<br>**So that:** I can evaluate mean resolution times (MTTR) and stock costs. | • Real-time dynamic panel fed by assets compiled via NPM/Vite using the **Chart.js** library.<br>• Optimized SQL queries with eager loading (`with()`) to prevent N+1 query performance issues. |
| 🟢 **Medium** | **As:** Authenticated User<br>**I want:** to add comments and attach photos to the ticket<br>**So that:** I can detail the technical trail and fault evolution evidence. | • Bilateral communication channel. Logical restriction on Back-End: Workers can only comment on their own tickets (`TicketController@addComment`).<br>• Secure image file storage through Laravel's `Storage` filesystem. |
| 🟢 **Medium** | **As:** User / Technician<br>**I want:** to be reactively notified in the browser and by email<br>**So that:** I can follow state changes and messages instantly. | • Integration with **Laravel Echo / WebSockets** to push reactive notifications (*Broadcast*) that update the interface without page reload.<br>• Asynchronous email dispatch in the background integrated with SMTP servers (e.g., Mailtrap). |
| 🟢 **Medium** | **As:** Administrator<br>**I want:** to export corporate data and track the modification trail<br>**So that:** I can generate physical reports and guarantee immutable ecosystem auditing. | • Generation and download of consolidated reports in **PDF and Excel** format with advanced filters.<br>• Audit table (`audits`) storing modified values in JSON format (`old_values` and `new_values`) with the user's IP and agent. |
| 🟢 **Medium** | **As:** Developer / Integrator<br>**I want:** to access live endpoint documentation<br>**So that:** I can consult the application's JSON request and response schemas. | • Automatic mapping and interactive API documentation exposed locally through the **Swagger / OpenAPI** interface. |
