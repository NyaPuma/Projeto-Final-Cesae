## Locale bug fix (language menu "stuck")

### Root cause
Multiple interacting bugs caused the language selection to appear non-functional:

1. **`PreferencesService::DEFAULTS['language']` was `'pt'` instead of `'pt-PT'`** — When no `user_preferences` row existed, this raw base code flowed through `LocaleService::sanitize()` which returned `'pt'` (since `meta('pt')` is null — only `'pt-PT'` is a config key). This caused `App::setLocale('pt')` to be called, which couldn't find translation files in `lang/pt/`.

2. **`SetUserPreferencesMiddleware` always overrode `SetLocaleMiddleware`** — Both middlewares called `App::setLocale()`, and the second one always won. For authenticated users without an explicit session locale, the second middleware read from `user_preferences.language` (defaulting to `'pt'`), overriding the correct locale from `SetLocaleMiddleware`.

3. **`PreferencesService::current()` couldn't find authenticated users on web routes** — `$request->user()` returned null because `CustomAuthMiddleware` sets the user on the `api` guard, not the web guard. So the modal's `$currentLanguage` fell back to session defaults and never matched any card's `data-locale`, making the UI appear stuck.

### Fixes applied
| File | Change |
|------|--------|
| `PreferencesService.php` | `DEFAULTS['language']` changed from `'pt'` to `'pt-PT'` |
| `LocaleService.php` | `sanitize()` now resolves base codes (e.g., `'pt'` → `'pt-PT'`) via base-matching fallback when `meta()` returns null |
| `SetUserPreferencesMiddleware.php` | Removed redundant `App::setLocale()` call — locale is now the exclusive responsibility of `SetLocaleMiddleware`. Removed unused `resolveLanguage()` and `hasExplicitLocale()` methods and their imports. |
| `PreferencesService.php` | `current()` now resolves user via `Auth::guard('api')->user()` and `AuthUserResolver::fromRequest()` as fallbacks, so authenticated users on web routes get their DB preferences instead of session defaults |
| `PreferenciasServiceTest.php` | Updated 3 assertions from `'pt'` to `'pt-PT'` |
| `UserPreferencesTest.php` | Updated 4 assertions from `'pt'` to `'pt-PT'` |
