## Session — Production & Deployment Readiness: Laravel Octane + FrankenPHP worker mode (2026-09-01)

**Rationale:** The Docker image (`dunglas/frankenphp:1.9.0-php8.2`) was running Laravel in *classic stateless* mode (`frankenphp run` + `php_server`, one framework boot per request) — correct but throwing away the main reason to use FrankenPHP. Installed and wired **Laravel Octane worker mode** so workers boot the app once and serve many requests.

**Changes:**
- `composer require laravel/octane:^2.19` → `composer.json` `require` (+`composer.lock`). Octane belongs in `require`, not `require-dev`: it is the production runtime (needed by the `dunglas/frankenphp` image), matching the Octane/FrankenPHP readiness item.
- Published `config/octane.php` (`php artisan vendor:publish --provider=Laravel\Octane\OctaneServiceProvider`), then:
  - `server` default `roadrunner` → `frankenphp` (matches deployment).
  - `max_execution_time` → `env('OCTANE_MAX_EXECUTION_TIME', 30)` (was hardcoded 30).
- `public/frankenphp-worker.php` committed (= Octane's own stub). **Required** because Octane would otherwise copy the worker file into `public/` at runtime — which fails on the image since the process runs as `www-data` and `public/` is root-owned and read-only. Shipping it pre-baked removes that RW dependency.
- `Dockerfile`:
  - `CMD` `frankenphp run --config /etc/caddy/Caddyfile` → `php artisan octane:frankenphp --host=0.0.0.0 --port=80 --admin-port=2019`. `--admin-port=2019` is mandatory: Octane derives it as `2019 + (port - 8000)`; with `--port=80` that computes a *negative* port and throws `InvalidArgumentException`. The `frankenphp` binary is already on PATH in the image (`/usr/local/bin/frankenphp`), so Octane's `ExecutableFinder` resolves it.
  - Added missing `php artisan storage:link` (plus `storage/app/public` mkdir) — `public/storage` symlink was never created in the image.
- `.env.example`: documented `OCTANE_SERVER` / `OCTANE_HTTPS` / `OCTANE_MAX_EXECUTION_TIME` / `OCTANE_STATE_FILE`.
- Note: the legacy `docker-compose.yml` (dev-style, `9000:9000`, volume `./:/var/www/html`, mysql `root/root`) does NOT match the current `Dockerfile` (`/app` WORKDIR, `:80`) or prod `compose.yaml` (`8000:80`, `./:/app`). Flagged; not rewritten (out of scope, and `compose.yaml` is the production artifact).
