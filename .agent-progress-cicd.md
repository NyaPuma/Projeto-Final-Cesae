## Planned Secret Configuration

Deployment requires GitHub Environment secrets for the production environment:

- `DEPLOY_HOST`: production hostname or IP address.
- `DEPLOY_USER`: SSH deployment user.
- `DEPLOY_SSH_PRIVATE_KEY`: private key for the deployment user.
- `DEPLOY_KNOWN_HOSTS`: pinned SSH host key entry or entries.
- `DEPLOY_PATH`: absolute path to the zero-downtime release directory.
- `DEPLOY_HEALTHCHECK_URL`: HTTPS URL for the deployed `/up` endpoint.
- `DEPLOY_PORT`: optional SSH port; defaults to `22` in the workflow.
- `DEPLOY_SERVICE`: systemd service that supports a zero-downtime reload.

No credentials, hostnames, IP addresses, or API keys will be committed to workflow files.

### Continuous Deployment

- Added `.github/workflows/deploy.yml`, triggered after a successful `CI` run on `main` or manually from `main`.
- The deployment creates a SHA-named release, uploads source without secrets or generated dependencies, installs production dependencies, builds assets, migrates, caches Laravel configuration, atomically switches `current`, restarts queues, and reloads the configured service.
- The workflow verifies the secret-configured health URL and rolls back to the newest previous release on failure.
- The target server must provide PHP, Composer, Node.js/npm, rsync, systemd, a shared `.env` at `$DEPLOY_PATH/shared/.env`, and passwordless permission for the configured service reload.
